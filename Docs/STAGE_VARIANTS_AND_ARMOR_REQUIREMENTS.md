# 스테이지 변형·시작 카드·방어력 밸런스 요구사항

## 1. 사용자 요구사항

1. Stage02와 Stage03은 서로 다른 전장이어야 한다.
   - 이동 경로, 지형 비율, 건설 지점, 장식 배치와 전투 콘텐츠 연결이 구분되어야 한다.
   - 씬 시드만 다른 복사본은 별도 스테이지로 인정하지 않는다.
2. Stage01~03은 서로 다른 시작 카드를 지급해야 한다.
   - 지급 원본은 각 스테이지의 전투 콘텐츠 JSON `run.startingCards`다.
   - 스테이지 선택 화면은 선택한 스테이지가 실제 지급할 카드의 현지화된 이름을 시작 전에 표시해야 한다.
   - UI용 카드 목록을 별도로 하드코딩하지 않는다.
3. 한 번에 여러 대상을 공격하는 피해와 화상은 방어력이 조금만 높아도 빠르게 약해져야 한다.
   - 군집 웨이브는 낮은 체력의 다수를 광역/연쇄 공격으로 정리하는 역할을 유지한다.
   - 봉쇄전은 적은 수의 고체력·고방어 적에게 상태이상을 여러 번 중첩하거나 방어를 파괴하게 만든다.
   - 중독의 방어 무시, 관통과 부식의 방어 대응 역할은 유지한다.

## 2. 스테이지 설계

| 스테이지 | 전장 정체성 | 시작 카드 | 빌드 학습 목표 |
| --- | --- | --- | --- |
| Stage01 | 짧은 기본 굴절 경로 | `split`, `burn`, `explode`, `poison` | 생성, 화상, 폭발, 지속 피해 입문 |
| Stage02 | 세로로 긴 12회전 오르막 | `pierce`, `mark`, `poison`, `corrosion` | 방어 무시, 표식, 중독, 방어 파괴 |
| Stage03 | 가로로 긴 다리 행군 경로 | `ricochet`, `bleed`, `knockback`, `shock` | 연쇄 타격, 이동 출혈, 밀치기, 감전 |

Stage03은 Stage02 씬을 최종 결과로 복사하지 않는다. 공유 Fields 에셋과 검증 파이프라인은 재사용하되 다음 권위 데이터를 별도로 가진다.

- `stage03-content.json`
- `StageThreePresentationCatalog.asset`
- Stage03 전용 경로와 12개 건설 지점
- Stage03 전용 가로형 지형 타일 배치와 장식 스펙
- Stage03 전용 시뮬레이션 시드

## 3. 시작 카드 UI 설계

메인 메뉴 씬은 세 스테이지의 콘텐츠 JSON과 공통 전투 로컬라이제이션을 참조한다. `StageSelectionMenu`는 선택된 스테이지의 `run.startingCards`를 읽고 `StageOneUiTextCatalog.GetCardName`으로 이름을 변환해 다음 형식으로 표시한다.

```text
시작 카드 · 관통 · 표식 · 중독 · 부식
```

따라서 전투 콘텐츠의 시작 카드가 변경되면 메뉴도 같은 데이터를 읽으며 자동으로 갱신된다. 빌드 전 검증은 세 콘텐츠 참조가 모두 존재하고 세 시작 카드 배열이 서로 다른지 확인한다.

## 4. 방어력 공식 설계

기본 공식은 기존의 유리수 감쇠를 유지하고 피해 성격에 따라 방어 민감도만 바꾼다.

```text
유효 방어력 = Armor × (1 - ArmorIgnore)
가중 방어력 = 유효 방어력 × ArmorSensitivity
최종 피해 = 사전 피해 × ArmorScale / (ArmorScale + 가중 방어력)
```

초기 데이터 값은 다음과 같다.

| 피해 성격 | ArmorSensitivity | Armor 10 | Armor 42 | Armor 84 |
| --- | ---: | ---: | ---: | ---: |
| 단일 대상/일반 지속 피해 | 1.0배 | 90.9% | 70.4% | 54.3% |
| 화상/화염 | 4.0배 | 71.4% | 37.3% | 22.9% |
| 광역·폭발·감전 연쇄 | 5.0배 | 66.7% | 32.3% | 19.2% |

- 광역 화상처럼 두 조건이 겹치면 배율을 곱하지 않고 더 높은 민감도 하나만 적용한다.
- 중독은 기존 카드 데이터의 방어 무시를 적용한 뒤 일반 1.0배 민감도를 사용한다.
- 출혈 등 단일 대상 지속 피해는 일반 민감도를 사용하므로 고방어 적 대응 빌드가 사라지지 않는다.
- 화상은 중첩 수만큼 사전 피해가 선형 증가한 뒤 방어 감쇠를 한 번 적용한다. 높은 방어력에는 충분한 중첩 또는 관통/부식 보조가 필요하다.
- `shock_chain`처럼 여러 적을 한 번에 고르는 효과는 `Area` 태그를 사용해 같은 공식을 공유한다.

조절 가능한 작성 원본은 모든 스테이지 콘텐츠에 공통으로 복제되는 다음 필드다.

```json
"armorMitigationScale": 100,
"areaArmorSensitivityBps": 50000,
"burnArmorSensitivityBps": 40000
```

## 5. 완료 조건

- Stage02와 Stage03의 맵 종횡비, 경로 좌표, 건설 지점과 콘텐츠 자산이 다르다.
- Stage01~03 시작 카드 배열이 위 표와 일치하고 서로 중복 구성이 아니다.
- 스테이지 선택 UI가 실제 콘텐츠에서 읽은 현지화 카드 이름 4개를 표시한다.
- 방어력 42에서 같은 사전 피해의 광역 피해가 단일 대상 피해의 절반 미만 수준으로 감소한다.
- 화상은 일반 단일 대상 피해보다 방어에 민감하고, 중첩량에 대해서는 선형성을 유지한다.
- 감전 연쇄 등 다중 대상 피해가 광역 방어 공식을 사용한다.
- 관련 EditMode/PlayMode 테스트와 전체 WebGL 빌드가 성공한다.
